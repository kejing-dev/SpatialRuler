# 空间尺 Spatial Ruler · 产品需求文档 PRD

版本 1.0.0 · 2026-10-06 · PICO OS 6 · PICO Spatial SDK 6.1.9

## 1. 一句话 One line

一把长在房间里的卷尺：在真实表面上落下测量钉，任意两颗钉之间拉出一条按 1 : 1 刻度印好的尺带，读数骑在尺带上，并且说明这次量得有多准。

A tape measure that lives in the room: set pins on real surfaces, pull a true-scale tape between any two of them, and read the distance on the tape together with how precise it is.

## 2. 背景与问题 Background

- 现场测量靠卷尺或激光测距仪，再手抄数字；过后只剩一张数字表，指认不了当时量的是哪里。
- 手机 AR 测量隔着一块屏去点：有视差和手指遮挡，沿视线方向的深度看不见；结果是平面列表「A–B 1.204 m」，钉超过三颗就得靠记忆把名字对回实物。
- 一个数字不说明自己有多准，而头显里落点的精度随输入方式差好几倍（设计假设，未经设备验证：手柄触测 ±2–3 mm，系统指点 ±8 mm + 0.5 %·距离）。
- PICO OS 6 的 Full Space 有透视、平面识别、空间锚点和 6DoF 的手柄与手：点本来就在房间里，可以直接指、直接碰，侧身一步就能复核；尺可以 1 : 1 铺在被量的东西上，下次打开还在原处。

## 3. 用户与场景 Users and context

| 项 | 内容 |
| --- | --- |
| 用户 | 戴 PICO OS 6 头显的人，在家、办公室或工坊里量桌子、门洞、窗、柜子的空位 |
| 场景 | 站着或走两步，一只手可能正扶着东西，会伸手、会下蹲。不假设长时间佩戴：戴上，一分钟内量完，摘下 |
| 空间 | Full Space · Stage · Mixed（一个 Mixed Stage，MR 透视），不是 Shared Space 窗口。量室内 0.05–6 m 的点到点直线距离；读数在 0.3–5 m 都要读得清，唯一的控制面在伸手可及处（约 0.6 m） |
| 输入 | 手柄和手势并重：手柄射线（扳机半按细瞄）、手部射线、手柄尖或捏合点触测、系统指点（注视 + 捏合；模拟器里鼠标 = 注视，单击 = 捏合）。主流程只靠系统指点就能走完 |
| 启动 | 打开即可落第一颗钉：没有引导向导、没有模式菜单，首次只有一句话的引导 |
| 语言与单位 | 中文 / English，应用内即时切换（默认跟随系统）；m / cm / mm / ft·in |

## 4. 唯一任务 The single job

把现实里的两个点，变成一个**敢拿去用**的距离读数。「敢用」= 看得见量的是哪两点 + 数值 + 这次量得有多准。列表、设置、持久化都只为这一件事服务。

Turn two real points into a distance you can act on: you see which two points were measured, the value, and how precise this measurement is.

## 5. 为什么要做成空间应用 Why spatial

| 核心任务 | 空间版为什么更好 | 2D 对照 |
| --- | --- | --- |
| 把钉落在真实的点上 | 点本来就在房间里；立体视觉加 6DoF 的工具尖或射线直接给出三维位置，侧身一步就能复核，不占手 | 手机 AR 测量：隔着屏去点，有视差和手指遮挡，看不见视线方向的深度；或卷尺加手抄 |
| 在原位读两点间的距离 | 尺带 1 : 1 铺在被量的东西上，数字就挂在那一段上，不必在名字和位置之间来回对照 | 平面列表「A–B 1.204 m」：钉超过三颗就得靠记忆对回实物 |
| 复核与微调精度 | 侧过身就能看出钉有没有离面、偏了多少；尺带跟着微调实时伸缩 | 屏幕放大镜加重新点击；深度方向的误差在单一视角里看不出来 |
| 给任意两颗钉连线 | 直接指向那两颗钉，连出来的就是它们之间那条尺 | 两个下拉框或 N × N 距离矩阵。总览全部配对时矩阵其实更高效，所以不做「全部配对常显」，只在选中一颗钉时亮出候选线 |
| 重开后找回 | 钉和尺回到原处，可以接着量，也可以复核 | 只剩一张数字表，指认不了当时量的是哪里 |
| 单位、语言、撤销、清除 | 没有空间收益：保持 2D，缩到最小 | 普通 2D 控件就够 |

形态结论：Full Space · Stage · Mixed。透视、平面识别、空间锚点、手柄与手部追踪只在 Full Space 可用，而且被量的东西比任何窗口都大。

## 6. 形态与布局 Form and layout

设计比较了三个方向，选 **A 拉尺 Pull-tape**：每次测量是从一颗钉到另一颗钉的一次「拉」，手柄、手势、注视、模拟器鼠标共用同一套心智模型，两下出读数，工具本身是有刻度、会伸、会吸、会定的实物。**B 触针 Touch-probe** 落选：每个点都要走到、够到，不适合一分钟会话；模拟器里没有手可碰，系统指点只能另做一套替身；徒手接触约 ±8 mm，撑不起「触针 = 精确」。它的触测档保留下来。**C 放样 Layout** 落选：精度全押在平面识别上（拟合误差 1–2 cm 量级，用户无法微调），标注线和跟头细条都不是实物。它的吸附和选中时的候选线保留下来。

房间里只有三样实物，加上骑在尺带上的读数牌：

| 实物 Object | 样子 | 行为 |

## 7. 功能需求 Functional requirements

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| F1 | 点—点：系统指点点一下表面落一颗钉；没有尺头时它成为尺头，已有尺头时它是尺尾，尺带拉过去并落定，读数牌到中点，尺身读数窗同步显示 | 必须 |
| F2 | 按住拉出：在表面上按住、拖动、松开，尺带实时伸长；系统拖动按「指向线」规则换算成尺尾（手移 1 cm，指向线绕头部转约 1.2°）；按住钉上尺头的钩子拖动，从这颗钉拉出一条新尺 | 必须 |
| F3 | 追踪射线：手柄射线或手部射线，贴面准星 + 稳定环 + 实时尺带；扳机半按 = 4 : 1 减速细瞄（×4），全按落钉，位置取按下前 40–120 ms 的中值 | 必须 |
| F4 | 触测：手柄尖或捏合点离表面 12 cm 内自动接管，位置取工具尖本身（只吸附已有的钉），是最高的精度档 | 应该 |
| F5 | 任意两钉：点一颗钉选中它（成为尺头），到最近 6 颗未连尺的钉亮出候选线与距离片，无关的尺退到 55 % 不透明度；再点另一颗钉或距离片，两钉之间拉出一条尺；同一对钉只有一条尺 | 必须 |
| F6 | 档位与公差：每颗钉落下时定档 ◆ 触测 / ● 细瞄 / ○ 粗瞄；公差 = 触测 2 mm（捏合 8 mm）、细瞄 3 mm + 0.1 %·距离、粗瞄 8 mm + 0.4 %·距离、吸附到角或边 6 mm，超过 3 m 加倍；一条尺取两端平方和开根，只向上取到 2 / 3 / 5 / 8 mm、1 / 1.5 / 2 / 3 / 5 / 8 cm、10 / 15 / 20 / 30 / 50 cm，再大写 > 50 cm；≥ 1 cm 末位变淡，≥ 10 cm 末两位变淡 | 必须 |
| F7 | 拖动钉校位：按住钉拖动、松手落定；移动时 1 : 1，静止 400 ms 后自动 1 : 4（准星旁 ×4），一动快（> 4°/s）立即回 1 : 1；拖到别的面上改贴那个面；连着的尺与读数实时变化；一步撤销回原位 | 应该 |
| F8 | 步进器：钉条上 ‹ › ˅ ˄ 沿钉所在表面每格 1 mm，读数实时变化；校位后档位升为细瞄 | 必须 |
| F9 | 吸附（「更多」里可关，设置保存）：已有的钉 > 识别面的角 > 边 > 相对尺头的垂直 / 水平；有准星时按视角半径判定，系统指点时只吸被点中那个面的座，且限 40 mm（角）/ 30 mm（边、垂直、水平），落钉后补 0.8 s 座标记 | 应该 |
| F10 | 单位：尺身分段 m / cm / mm / ft·in 即时换算全部读数（1.204 m、120.4 cm、1204 mm、3′ 11.4″）；英制公差 8 cm 及以下取到 0.1″，再大取整英寸，超过写 > 20″ | 必须 |
| F11 | 语言：「更多」里的分段 跟随系统 / 中文 / EN，在原处即时切换，不重启 Stage | 必须 |
| F12 | 持久化：钉即空间锚点，随落随存（钉牢中 → 已保存；失败则未保存 + 重试）；偏移超过 50 mm 时在钉的新位置重建锚点；重开后钉和尺在原处找回并报数；不在此空间的钉隐藏，可一键清除；单位、语言、吸附、引导已看过一并保存 | 必须 |
| F13 | 撤销与删除：尺身撤销最近 20 步（落钉、拉尺、删除、收回、校位；一次按住拉出算一步）；钉条删除钉（连着的尺一并收回）；尺条收回一条尺 | 必须 |
| F14 | 全部清除与退出：「更多」→ 全部清除 → 确认对话框（不可撤销；没有钉时禁用）；退出关闭 Stage，钉和尺都已保存 | 必须 |
| F15 | 上限与边界状态：最多 20 条尺（第 21 条不建，提示先收回一条），钉不设上限；没有表面 / 还在识别；超过 3 m（▲，公差加倍）；定位丢失（钉与尺去色、读数冻结 ⦸）；能力不可用（对话框：退出 / 重试）；追踪输入源消失 3 s（提示抬手或拿起手柄） | 必须 |
| F16 | 声音与触感：落钉、吸附、尺带落定、收回、失败各有音效与手柄触感，每一项都有对应的可见变化 | 应该 |
| F17 | 设计里有、还没做：钉的悬停环、识别面轮廓闪现、钉落定晃动、短尺引线、追踪射线下的按住拉出 | 以后 |
| F18 | 不在本版：面积、角度、体积、导出；两面净距、水平 / 垂直分量拆解 | 以后 |

## 8. 非功能需求 Non-functional

- **精度**：每个读数自带 ±，这条契约不变，只调常数；F6 的公差常数是设计值，待真机标定。落点本身不额外引入误差：钉要落在点中的那一点上（实测见第 9 节）。
- **帧率**：目标 60 fps。每帧工作只在一个注册的 ECS `System`（`RulerScene.onFrame`）里做，不经过 Compose 状态（只有拉出计数、可见面板、读数牌宽度三样，每秒最多写 10 次）；网格共享，每帧最多新建一个；动效按时间推进，模拟器 2–4 fps 时任何状态不靠动效也能看懂。
- **启动**：尺身面板最先出现，不等任何网格；偏好读出前读数窗只转圈，不先用默认语言或单位画一遍；网格在帧之间逐个建，不整段阻塞主线程。设计估计真机约 3 s 就绪。
- **可读性**：房间里的面板按观看距离缩放（0.45–6 m 恒定视角），每帧转向头部（俯仰 ±60°，不滚转）；面板四角离识别面至少 2 cm；单块面板高 ≤ 720 dp，1 dp = 0.8 mm。
- **无障碍**：每个只有图标的控件和状态符号都有中英文描述（`rs()`），JVM 测试 `StringsResourceTest` 检查键、中文镜像和字数预算；按键热区 ≥ 56 × 48 dp，相邻控件中心距 ≥ 56 dp；系统指点路径上不需要长按；▲ ⦸ ◆ ● ○ 与颜色互为冗余；数字等宽，读数变化时不抖。
- **对比度**：玻璃上的文字只用 `labelPrimary`，深色实底上用 `labelPrimaryLight`；语义色作底时内容色用 `tapeInk`（5.9 : 1；白字在 `error` 上只有 2.7 : 1）。
- **UI 与字体**：全部 2D UI 用 SpatialUI（`com.pico.spatial.ui.*`）包在 `PicoTheme` 里，不用 Material / Material3；颜色只来自主题角色和品牌 token。Noto Sans + Noto Sans SC 子集随包（子集里缺的两个符号，含 ⦸，交给系统回退字体）。
- **架构**：领域层纯 Kotlin、不含 SDK 类型；单向数据流：事件 → `ReduceRulerUseCase` → 效果 → `RulerUiState` → 实体与面板；共享资源 `toGlobal()`，在 `detach` 时关闭。

## 9. 验证与证据 Verification and evidence

全部在 PICO 6.1 模拟器（emulator-5556，AVD `PICO_6.1_Ruler`）上完成。

- **单元测试**：254 个 JVM 测试全部通过（第 5c、5d 轮门禁），覆盖每个 use case、reducer、会话 JSON 编解码和 ViewModel。
- **门禁**：`tools/dev.sh gates`（交接回执、实现扫描、构建、启动、架构、单元测试、design-style：只用 SpatialUI、颜色只来自 token）通过。
- **QA**：7 轮报告（1、2、3、4、5、5b、5c），用真实注入的输入（发到模拟器窗口的鼠标消息 = 注视 + 捏合；手柄模式下 = 手柄射线 + 扳机），调试广播只用于布置场景和读回。第 4 轮（图标优先）结论 PASS，只有 3 个 S4：74 组点击序列、135 次真实目标按压，每次都对过日志，落在目标像素 2 px 内；每个图标控件真实捏合 3/3；0 崩溃、0 `RIG violation`。
- **字数（第 4 轮，en / zh）**：尺身、读数牌、距离片、两条图标条、准星标签全部 0；菜单 2 词 / 4 字；清除对话框 6 词 / 11 字；能力不可用对话框 13 词；引导 7 词 / 9 字；提示条每条 ≤ 5 词、≤ 9 字（动作按钮另计）。
- **放置精度（第 1 轮）**：12 颗钉，1.70–6.35 m，落在地面、床、墙、天花板、柜顶：每颗未吸附的钉重投影到点击像素 ≤ 1.8 px，离面 ≤ 0.07 mm；系统点击的命中点与解析平面求交相差 0.2–0.6 mm（里程碑 1）；步进器每次挪 1.00–1.02 mm；公差模型逐项对过设计常数。
- **手柄模式（第 4 轮）**：单击 → `TAP pointer kind=controller steady=true grade=fine`，钉正落在准星上（0 mm）；同一次按压到达的系统点击被丢弃（一次按压一个动作）。
- **拖动**：系统拖动的位移模型用 36 次拖动（150 / 250 px，1.4 / 2.5 / 3.5 m，平视与俯视 20–40°）联合拟合，rms 5.9 px，模拟器自身的重复离散约 4 %。第 5c 轮 QA：平视 4 次中 3 次达标（250 px 拖动停在 ≤ 10 px，150 px ≤ 8 px）；俯视（偏航 88°、俯仰 −38°）8 次中 3 次达标，其余停在光标后 10.9–14.5 px（R5c-1，S2）；停 1 s 后快拖 100 px，0.5 s 内只走 74–78 px（目标 ≥ 85，R5c-2，S3）；拖动后撤销精确回原位（0.00 mm）。第 5、5b 轮 FAIL，第 5c 轮 not ship；第 5d 轮改了 ×4 规则，之后没有 QA 报告。
- **帧率**：第 4 轮 8 条尺时应用 59.7–60.3 fps，20 条尺时 55 fps；第 5c 轮在 8 条尺中拖钉，合成器 60 / 49 fps，应用 37.8 / 52.5 fps。
- **启动（第 4 轮）**：尺身面板在启动后 0.9 s 画出，场景构建 17.9 s（模拟器空闲帧率）。
- **回归（第 4 轮）**：点—点、钉 → 距离片 → 尺、收回、撤销 8/8、单位、语言、全部清除（取消 3/3、清除 4/4）、重开找回、退出再开 3/3、按住拉出、校位超过 50 mm → 重建锚点 → 撤销，全部通过；第 5c 轮的回归也全部通过。

## 10. 边界与未验证 Limits and unverified

- **没上过头显**：以上全部只在模拟器上跑过；真机上的舒适度、遮挡、物理尺寸、输入命中、追踪精度、性能都没有验证。
- **手部追踪**：模拟器没有手。`HandPointerSource` 在模拟器上不启动，由合成指针代替；手部射线和捏合点触测只跑过代码路径。
- **模拟量扳机**：模拟器手柄模式的扳机只有 0 / 1，没有半按；半按 4 : 1 细瞄只用合成指针测过（`trigger s=half` 显示 ×4）。
- **手柄尖**：触测用的是手柄位姿前 6 cm 的虚拟针尖，真实尖端偏移没有标定。
- **触感与声音**：代码已接，模拟器里感觉不到、听不到。
- **权限**：真机上平面识别、空间锚点、手部追踪要不要运行时权限未知（模拟器不需要）；拿不到时进入「空间能力不可用」。
- **锚点漂移**：重定位后锚点整体刚性变换只部分验证（spike：整体转 8.8°，两点间距 0.7348 → 0.7346 m）；运行中重定位时锚点会不会发更新事件没有验证；平面四边形每次启动都不同（床角两次启动之间差 15 cm）。读数总由两端钉的当前位置算出。
- **拖动标定只适用于模拟器**：系统拖动的位移模型（`equivalentDepth`）是在模拟器上拟合的，那里的虚拟手跟着注视走；指向线的换算系数也只是起始值。真机上都要重调；R5c-1 没有复测。
- **公差常数**：设计值，没有对照真机标定。
- **已知小问题**：读数牌多到放不下时会互相压住；有光照的黄色因色调映射对不上 token；大角度转头后尺身可能停在偏左约 20°（R3-3）。
- **范围**：只量点到点直线距离；按一次 2–12 颗钉、1–8 条尺设计。
